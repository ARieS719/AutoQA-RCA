# RCA 报告：远程解锁显示失败但链路实际成功

- 案例 ID：`case_5_ui_but_link_ok`
- 生成时间：2026-10-25 21:56:26
- 运行模式：llm
- 分诊结论：UI轨=是，车联轨=是（依据：用例元数据声明链路依赖（domain=mixed）；link_dependency=cloud,tbox,can）

## 1. 故障现象 (What)
车机显示远程解锁失败，但云端状态为 SUCCESS

## 2. 根因定性 (Why)
车门解锁成功后，状态同步服务处理返回状态时未做空值校验，导致UI进程崩溃

## 3. 责任判定 (Who)
座舱软件团队（状态同步服务开发组）

## 4. 仲裁说明（双轨交叉验证）
轨B 证实链路完整闭环（指令送达、总线应答、状态回传均成功）——链路无责，责任回摆座舱应用层，由轨A 收口定责。

启动即抛 ArrayIndexOutOfBoundsException 导致进程死亡。
修复方案：增加数组边界检查，越界时返回默认焦点策略并打点上报。

## 6. 修复建议 (Action)
- 在StatusSyncService中增加对statusPayload的空值防御逻辑
- 补充状态同步异常场景的单元测试用例
- 检查其他状态同步接口是否存在类似空值风险

## 附：轨A｜UI/座舱域详细产出
关键线索摘要：

1. 失败步骤：Step 3断言阶段失败，但实际崩溃发生在Step 2车门解锁操作后（18:40:01.600）

2. 应用层异常：
- 致命崩溃：StatusSyncService线程发生空指针异常（statusPayload is null）
- 进程死亡：com.ivi.remote进程异常终止
- 注意：车辆控制实际执行成功（BCM状态00），但状态同步服务崩溃

3. 缺陷类型：
- 纯逻辑缺陷：状态同步服务未处理空payload情况（NullPointerException）
- 与网络/链路无关：MQTT消息接收和CAN指令发送均正常（0x3F2解锁指令执行成功）

根本原因：车门解锁成功后，状态同步服务处理返回状态时未做空值校验，导致UI进程崩溃，进而使后续断言失败。属于典型的异步状态同步逻辑缺陷。

## 附：轨B｜车联网链路域详细产出
ID 0x3F2 解码为: 车门控制模块(BCM) - 远程解锁指令 (优先级: 中)
ID 0x3F3 解码为: 车门控制模块(BCM) - 解锁执行状态反馈 (包含状态码)

总结：### **CAN ID 解码结论总结**

1. **`0x3F2`（TX - 发送）**
   - **模块**：车门控制模块（BCM - Body Control Module）
   - **含义**：远程解锁指令
   - **优先级**：中
   - **说明**：该ID用于TBOX向BCM发送远程解锁命令，表明系统已触发解锁操作。

2. **`0x3F3`（RX - 接收）**
   - **模块**：车门控制模块（BCM - Body Control Module）
   - **含义**：解锁执行状态反馈（含状态码）
   - **说明**：该ID用于BCM向TBOX反馈解锁执行结果（如成功/失败/异常等）。

### **关联分析**
- **`0x3F2`（解锁指令）** 和 **`0x3F3`（状态反馈）** 构成完整的解锁通信链路，表明：
  - TBOX 发送解锁指令（`0x3F2`）→ BCM 执行并返回状态（`0x3F3`）。
  - 日志显示解锁成功（`unlock`指令已执行），但后续状态同步服务（`StatusSyncService`）因空指针崩溃，说明问题与CAN通信无关，而是云端状态同步逻辑缺陷。

### **结论**
- **CAN通信正常**：解锁指令（`0x3F2`）和状态反馈（`0x3F3`）均符合预期，排除车辆总线通信问题。
- **问题根源**：`StatusSyncService` 在解析云端状态推送（`/vehicle/tbox/status`）时未处理空负载（`statusPayload`为`null`）。

**建议修复方向**：增强状态同步服务的鲁棒性，增加空值检查和异常处理逻辑。
